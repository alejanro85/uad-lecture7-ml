# Шаблоны промптов для создания веб-форм с помощью LLM

Подходят для любого ассистента, который пишет код (Perplexity, GigaChat, YandexGPT, ChatGPT и др.).
Замените поля в фигурных скобках `{{…}}` на данные своего проекта. Чем точнее описаны признаки и цена ошибок, тем полезнее получится форма.

Общее правило: **сначала модель в блокноте, потом форма.** Форма только показывает модель, которую вы уже проверили по шагам 1–10.

---

## 1. Форма Gradio в Colab (самый быстрый путь к ссылке)

```text
Роль: ты — аналитик данных и преподаватель. Пиши код на Python для Google Colab с комментариями на русском.

Контекст: у меня обученная модель sklearn `model` (Pipeline с предобработкой и LogisticRegression),
таблица признаков `X` и тестовая выборка `y_te`, `proba` (вероятности класса 1).
Датасет: {{название и raw-ссылка на CSV в GitHub}}.
Событие (класс 1): {{например, «отказ насоса»}}.
Числовые признаки с единицами: {{список: имя столбца — подпись — единицы}}.
Категориальные признаки: {{список}}.
Ложная тревога означает: {{последствие}}. Пропуск означает: {{последствие}}.

Задача: напиши одну ячейку с веб-формой Gradio (gr.Interface):
- ползунки для числовых признаков с диапазоном от 1-го до 99-го перцентиля X и значением по умолчанию = медиана;
- выпадающие списки для категорий со значением по умолчанию = мода;
- ползунок порога решения 0,05–0,95;
- вывод: gr.Label с вероятностями двух классов и gr.Markdown с решением,
  числом найденных событий и ложных тревог на тестовой выборке при этом пороге и пояснением цены ошибок;
- запуск demo.launch(share=True).
Не используй признаки, которых нет в X. Добавь в конце проверку: вероятность из формы для первой строки X_te
совпадает с model.predict_proba.
```

## 2. Многостраничное приложение Streamlit

```text
Роль: ты — разработчик аналитических веб-сервисов на Streamlit.

Сделай файл app.py и requirements.txt для приложения «{{название}}» по датасету {{raw-ссылка}}.
Вопрос бизнеса (шаг 1): {{вопрос}}. Целевая переменная: {{как получить 0/1}}. Признаки: {{список}}.
Очистка (шаги 2–4): {{что делаем с пропусками, ошибками, опечатками}}.

Структура — вкладки:
1. «Данные»: размер, доля события, первые строки, описательная статистика.
2. «Разведка»: гистограмма выбранного признака по классам, доля события по категориям, корреляции с целевой.
3. «Модель и порог»: StandardScaler + OneHotEncoder + LogisticRegression, разбиение 75/25 со stratify,
   базовая линия (самый частый класс), ROC-AUC, ползунок порога, матрица несоответствий с подписями
   «найдены / пропуск / ложная тревога / верно», поля цены ложной тревоги и пропуска,
   график суммарной цены ошибок от порога с отметкой минимума, веса модели.
4. «Форма "что если"»: поля всех признаков в st.form, кнопка «Рассчитать», вероятность и решение.

Требования: кэшировать загрузку и обучение (st.cache_resource), подписи по-русски с единицами,
цвета: основной #37B34A, тёмный #244128, акцент #724796, события-риски — #DA4927. Без лишних библиотек:
streamlit, pandas, numpy, scikit-learn, plotly.
```

## 3. Статическая страница без сервера (GitHub Pages)

```text
Роль: ты — фронтенд-разработчик. Нужна одна страница index.html без сборки и без фреймворков.

Я выгружу из Python JSON такого вида:
{ "num": [имена], "mean": [...], "scale": [...], "num_coef": [...],
  "cat": {"признак": ["значение1", ...]}, "cat_coef": [...], "intercept": число,
  "test": {"y": [0/1...], "p": [вероятности...]} }
Напиши: (а) Python-код экспорта этого JSON из sklearn Pipeline(StandardScaler, OneHotEncoder, LogisticRegression);
(б) index.html, который читает models.json и показывает:
- форму с ползунками и списками, вероятность пересчитывается при каждом изменении по формуле
  p = 1 / (1 + exp(-(b0 + Σ b_i·(x_i − mean_i)/scale_i + Σ b_k·[категория = значение]))) ;
- ползунок порога, матрицу несоответствий, accuracy, precision, recall на тестовой выборке;
- график суммарной цены ошибок от порога (SVG, без библиотек);
- горизонтальные столбики весов: вправо — повышают вероятность события, влево — снижают.
Адаптивная вёрстка до 375 px, шрифт Onest, доступные подписи (label, aria-live для результата).
Добавь самопроверку: для 5 строк из JSON вероятность в браузере совпадает с sklearn с точностью 1e-3.
```

## 4. Форма прямо в ячейке Colab (Colab Forms)

```text
Напиши ячейку Google Colab, где параметры объекта задаются через Colab Forms (#@param):
ползунки для {{числовых признаков с диапазонами}} и списки для {{категорий со значениями}}, плюс порог.
Ячейка собирает DataFrame из одной строки с теми же именами столбцов, что в обучающей таблице,
и печатает вероятность события «{{событие}}» и управленческое решение «{{действие при событии}}» / «{{иначе}}».
```

## 5. Дашборд разведки без кода (Yandex DataLens, Looker Studio, Datawrapper)

```text
Роль: ты — BI-аналитик. Инструмент: {{Yandex DataLens / Looker Studio / Datawrapper}}.
Датасет: {{описание столбцов}}. Аудитория: {{руководитель службы …}}.
Предложи дашборд из 4–6 чартов для шагов 5–6 (разведка и тренды): для каждого чарта укажи тип,
измерения, показатели, вычисляемые поля (формулы на языке инструмента), фильтры и вывод,
который руководитель должен увидеть. Отдельно перечисли, что дашборд НЕ показывает
(прогноз и вероятность события — это задача модели, а не дашборда).
```

## 6. Сбор данных с аудитории для обратной задачи (Яндекс Формы / Google Forms)

```text

Составь анкету для сбора экспертных оценок / наблюдений: 6–8 вопросов, каждый соответствует признаку
будущей модели (тип поля, единицы, допустимый диапазон, обязательность), плюс вопрос-цель «{{событие}} да/нет».
Затем дай код Python, который читает выгрузку ответов (CSV), переименовывает столбцы в короткие имена
и проверяет диапазоны и пропуски. Если ответов мало, предложи, как дополнить их синтетическими данными
по описанию из блокнота 05 и как пометить синтетические строки.
```
